# 공대 파밍표

파이널판타지14 8인 공대의 시작 BiS 상태와 1~8주차 **실제 드랍·분배 이력**을 한 방에서 관리하는 웹 도구입니다. 방장은 매주 나온 아이템을 한 건씩 기록하고, 누적 수령 수와 아직 필요한 부위를 함께 반영한 다음 수령 후보를 확인할 수 있습니다.

## 비스표와 무엇이 다른가요?

두 앱은 목적과 저장 공간이 분리되어 있습니다.

| 앱 | 알맞은 상황 | 저장 방식 |
| --- | --- | --- |
| [비스표](../bis-maker/) | 오늘 한 번 취합하고, 나온 수량에 맞춰 단일 분배안을 빠르게 만들 때 | 한 방의 현재 BiS 상태와 일회성 분배안 |
| 공대 파밍표 | 같은 고정 공대로 최대 8주 동안 실제 수령 이력과 공정성을 이어서 관리할 때 | 주차별 드랍을 수정하지 않는 이벤트 원장으로 누적 |

공대 파밍표는 비스표 방을 변환하거나 공유하지 않습니다. 기존 비스표는 `bisRooms`, 공대 파밍표는 `raidLootRooms` 컬렉션을 사용하므로 이미 만든 일회성 방도 그대로 유지됩니다.

## 사용 흐름

1. 방장이 Google 계정으로 로그인합니다.
2. 공대명, 레이드 시즌, 1주차 시작일과 `MT`, `ST`, `MH`, `SH`, `D1`, `D2`, `D3`, `D4`의 닉네임·직업을 입력해 방을 만듭니다.
3. 공대원에게 개인 입력 링크를 공유합니다. 참여자는 별도 로그인 화면 없이 Firebase 익명 계정으로 자기 자리 하나를 선택합니다.
4. 각 공대원은 11개 장비 부위를 `완료`, `보강템 필요`, `영식템 필요` 중 하나로 제출합니다. 방을 잠그면 참여자 입력을 마감할 수 있습니다.
5. 방장은 1~8주차 탭에서 실제로 나온 아이템을 한 건씩 수령자에게 배정하거나 미배정으로 남깁니다.
6. 누적 수령 수, 남은 필요 부위, 분배 정책과 후보별 추천 근거를 확인합니다. 잘못 입력한 기록은 삭제하거나 덮어쓰지 않고 **되돌리기 이벤트**를 추가합니다.

분배 추천은 권장안입니다. 실제 공대 규칙이나 합의가 우선이며, 방장이 수령자를 직접 바꾸거나 공정성 집계에서 제외할 수 있습니다. 직접 드랍 무기는 해당 직업 공대원만 수령자로 기록할 수 있습니다.

BiS 입력 화면은 `무기`를 맨 위에 두고, 아래를 `머리 / 귀걸이`, `몸통 / 목걸이`, `장갑 / 팔찌`, `바지 / 반지 1`, `신발 / 반지 2`로 짝지어 보여 줍니다. 입력 화면과 8인 누적 현황표의 장비 분류 그림은 [XIVAPI](https://v2.xivapi.com/docs/guides/assets/)가 제공하는 파이널판타지14 게임 아이콘이며, 아이콘이 표시되는 화면에 저작권 표기를 함께 둡니다.

## 8주 이벤트 원장

드랍 원장은 다음 세 동작을 시간순으로 추가합니다.

- `award` — 주차·층·아이템·수령자·장비 부위와 추천/수동 결정 여부 기록
- `skip` — 드랍은 있었지만 미배정, 외부 처리 또는 보류한 사실 기록
- `undo` — 기존 `award` 또는 `skip`의 ID를 가리켜 그 효과를 취소

이미 저장한 이벤트 문서는 수정하지 않습니다. 되돌리기도 새 기록으로 남기므로 “누가 무엇을 받았는지”가 조용히 바뀌지 않고, 활성 기록만 통계와 다음 후보 계산에 반영됩니다.

방마다 `award`, `skip`, `undo`를 합쳐 최대 **480개 이벤트**를 저장합니다. 이 상한은 일반적인 8주 파밍에는 충분한 여유를 두면서, 방 삭제 시 이벤트 480개 + 공대원 8개 + 방 1개를 Firestore의 500개 쓰기 배치 안에서 원자적으로 정리하기 위한 값입니다.

## 로그인, 권한과 공개 범위

- 방 생성, 내 방 목록, 방 설정, 자리 연결 해제, 드랍 기록과 방 삭제는 Google 방장만 할 수 있습니다.
- 공유 링크로 들어온 공대원은 Firebase 익명 UID로 빈 자리 하나를 연결하고 그 자리의 장비 상태만 수정합니다.
- 방 링크를 정확히 아는 로그인 사용자는 8명의 닉네임·직업·장비 상태와 분배 이력을 읽을 수 있습니다. 링크를 공개 게시물에 올리지 마세요.
- Google 표시 이름과 이메일은 Firestore의 방 데이터에 저장하지 않습니다. 권한 확인을 위한 방장 UID와 이벤트 작성자 UID는 저장됩니다.
- 브라우저 저장 데이터나 시크릿 창을 지우면 익명 UID가 바뀌어 기존 자리를 수정하지 못할 수 있습니다. 이 경우 방장이 자리 연결을 해제한 뒤 다시 연결합니다.

Firebase 보안 규칙은 클라이언트 화면과 별도로 위 권한과 데이터 형식을 서버에서 검사합니다. 연결 방법은 [Firebase 설정 안내](./FIREBASE_SETUP.md)를 참고하세요.

## 실행과 테스트

별도 빌드 과정이 없는 정적 웹 앱입니다. 저장소 루트에서 실행합니다.

```bash
python3 -m http.server 8000
node --test raid-loot-maker/tests/*.test.js
```

로컬 주소는 `http://localhost:8000/raid-loot-maker/`, GitHub Pages 배포 주소는 `/raid-loot-maker/`입니다.
