# 파밍 모집표

극 토벌전 **5클 · 8인 파티**의 실제 모집·신청·편성을 관리하는 정적 웹 앱입니다. 접속: https://huis-snow.github.io/tools/farm-party/

## 화면과 동작

- **모집방:** 실시간 모집 목록, T1~D4 편성판, 신청자·대기 현황, 로그인 없이 저장된 정보로 신청
- **내 정보:** 닉네임·서버·메모, 자리별 불가/가능/선호, 7개 토벌전의 날개 기록
- **방장 화면:** Google 로그인, 내 모집방 선택, 자리 수동 배정·고정, 추천 편성, 확정·다시 열기·종료, 모집 링크·편성표 복사
- **새 모집:** 토벌전 복수 선택·출발 일시·제목·설명 입력, 이전 모집 설정 복제
- **이번 신청 변경:** 기본 프로필을 유지하면서 해당 모집의 자리·메모만 변경
- **공략 자료:** 선택한 토벌전별 영상 링크 표시. `trial-guides.js`에 으꺄 영상 6개와 09STOP 에누오 영상 1개를 등록했습니다.

로그인 전 내 정보는 공용 보관함의 `small-tools:farm-party:profile:v1` 키에 저장됩니다. **같은 브라우저에서만** 다시 불러옵니다. 저장 제한 시 현재 화면에서만 유지한다고 안내합니다. 저장 오류는 성공으로 표시하지 않습니다. 읽을 수 없는 기존 프로필은 복구 키에 보존하고 브라우저 저장을 중단합니다.

신청·모집방은 Firestore에 저장하고 실시간으로 갱신합니다. 신청값은 프로필의 복사본이므로 기본 정보 수정이 기존 신청을 자동으로 바꾸지 않습니다. 익명 신청의 수정 권한은 Firebase 익명 계정으로 유지합니다. 사이트 데이터를 지우거나 다른 브라우저로 이동하면 기존 익명 신청을 수정할 수 없습니다.

Google 계정을 연결하면 기본 프로필을 계정에 저장합니다. UID별 브라우저 캐시를 사용하며 다른 기기에서도 같은 계정으로 불러옵니다. 이미 연결된 계정으로 전환할 때는 기존 익명 신청이 자동으로 옮겨지지 않는다는 안내 후 전환합니다. 새 계정에 연결하면 익명 UID가 유지됩니다.

닉네임·서버·가능한 자리·선택한 토벌전별 날개·신청 메모는 모집방에서 공개됩니다. 7개 날개 기록을 포함한 기본 프로필은 본인만 읽고 쓸 수 있습니다. 확정·종료된 모집방은 신청 변경·취소를 받지 않습니다. 종료한 모집방은 공개 목록에서 빠지고 방장 목록·공유 링크에는 기록이 남습니다.

한 모집방에서 토벌전 1~7개를 선택하고, 같은 8인 파티로 각 토벌전을 5클씩 진행합니다. 신청 시 선택된 토벌전의 날개 기록만 공개합니다. 새 모집방은 version 2의 `trials` 배열과 신청자별 `wings` 맵을 사용하며, 기존 version 1의 단일 `trial`·`wing` 방과 공유 링크도 계속 읽고 신청할 수 있습니다. 모집 설정을 복제하면 선택한 토벌전 전체를 가져옵니다.

## 추천 편성

방장이 고정한 배정을 유지하고, 가능한 자리 안에서 배정 인원을 최대화한 다음 선호 자리 배정 수를 최대화합니다. 동일한 조건에서는 먼저 신청한 후보를 유지합니다. 날개 보유 여부는 표시만 하며 추천 점수에 반영하지 않습니다.

신청자는 최대 100명이고 8인 초과 신청은 대기합니다. 모든 변경은 트랜잭션으로 저장하고, 동시에 바뀐 방은 최신 revision을 읽어 재계산합니다. 편성 확정은 화면에서 확인한 revision이 서버와 같을 때만 가능합니다.

## 확인한 흐름

핵심 로직: `node --test farm-party/tests/core.test.cjs`

권한·동시 신청: `@firebase/rules-unit-testing`과 `firebase`를 설치하고, Firestore 에뮬레이터를 `demo-farm-party` 프로젝트·8080 포트로 실행합니다. `FARM_TEST_RUNTIME`을 두 패키지가 설치된 디렉터리로 지정하고 `node --test farm-party/tests/rules.test.cjs`를 실행합니다. 운영 데이터와 분리해서 검증합니다.

검증 범위: 편성·고정·신청 순서·100명 제한, 자기 신청만 수정·취소, 방장 권한, 프로필 비공개, 동시 신청, 최신 revision 확정, 종료 후 변경 금지.

## 배포 구성

- 화면: `huis-snow/tools` 저장소의 GitHub Pages
- Firebase 프로젝트: **`huis-snow-events`**, 표시 이름 `Guild Events`
- 기존 웹 앱: **`events-web`**, app ID `1:630794134680:web:325cf39b77fd10e5a9dced`
- 전용 컬렉션: `farmRooms/{22자리 방 ID}`, `farmProfiles/{UID}`
- 인증: Anonymous / Google, 허용 도메인 `huis-snow.github.io`와 개발용 localhost
- 규칙 원본: `huis-snow/events` 저장소의 `firestore.rules`. `firestore-rules.fragment`를 기존 규칙에 추가합니다. **tools의 dogoo-a697f 규칙을 이 프로젝트에 배포하지 마세요.**
- 복합 인덱스: `farmRooms`의 `status ASC + createdAt DESC`, `ownerUid ASC + createdAt DESC`

기존 이벤트 규칙·인덱스를 유지하면서 이 앱의 규칙·인덱스를 추가합니다. 공개 목록과 방장 목록은 각각 최근 30개를 표시하며, 더 오래된 방은 공유 링크로 접속할 수 있습니다. 익명 계정은 브라우저의 수정 권한 식별자이며 한 사람의 다중 신청·스팸을 완전히 방지하지는 않습니다.

별도 빌드 과정 없이 저장소를 정적 서버로 제공하면 됩니다.
